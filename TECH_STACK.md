# Рекомендуемый технологический стек для Necromunda Gang Wars

## Обзор

Этот документ описывает оптимальный стек технологий для веб-приложения Necromunda Gang Wars, ориентированный на:
- **Простоту поддержки** человеком без глубоких специализированных знаний
- **Бесплатность** всех инструментов
- **Низкий порог входа** и хорошую документацию
- **Распространённость** технологий (легко найти информацию и помощь)

---

## Рекомендуемый стек

### Frontend (клиентская часть)

**React + Vite + TypeScript**

**Почему:**
- **React** — самый популярный frontend-фреймворк, огромное сообщество, масса обучающих материалов на русском языке
- **Vite** — современный сборщик, очень быстрый, минимальная конфигурация
- **TypeScript** — помогает избежать ошибок при работе со сложными данными (характеристики бойцов, правила снаряжения)

**Альтернатива:** Next.js (если нужен SSR и SEO, но сложнее в освоении)

**UI-библиотека:**
- **shadcn/ui** или **Chakra UI** — готовые компоненты, адаптивный дизайн из коробки
- **Tailwind CSS** — для кастомизации стилей (очень популярен, простой синтаксис)

**Управление состоянием:**
- **Zustand** — простейший state manager (проще чем Redux)
- Для серверного состояния: **TanStack Query (React Query)** — кэширование, синхронизация данных

**Роутинг:**
- **React Router v6** — стандарт для навигации в React

---

### Backend (серверная часть)

**Node.js + Express + TypeScript**

**Почему:**
- **Node.js** — JavaScript на сервере, один язык для всего проекта
- **Express** — минималистичный, очень простой веб-фреймворк
- **TypeScript** — единообразие с фронтендом, безопасность типов

**Альтернатива:** **Fastify** (быстрее Express, но менее распространён)

---

### База данных

**PostgreSQL + Prisma ORM**

**Почему:**
- **PostgreSQL** — бесплатная, надёжная реляционная БД, идеально подходит для строгих связей: банда → бойцы → снаряжение → кампания
- **Prisma** — ORM с автогенерацией TypeScript-типов, интуитивный синтаксис, встроенная миграция схемы, визуализатор Prisma Studio
- Вместе с TypeScript даёт автодополнение прямо в редакторе — резко снижает количество ошибок

**Для MVP и локальной разработки:** SQLite — файловая база, не требует отдельного сервера, Prisma работает с ней без изменений кода

---

### Аутентификация

**Better Auth**

**Почему:**
- Готовая поддержка регистрации по email и OAuth (Google, GitHub)
- Бесплатна, хорошо интегрируется с Express + Prisma
- Не нужно разрабатывать авторизацию с нуля

**Альтернатива для совсем простого старта:** Firebase Auth — управляемый сервис Google, бесплатный тариф, почти нулевая конфигурация, но привязывает к экосистеме Google

---

### Хостинг и деплой (всё бесплатно)

| Компонент | Сервис | Бесплатный тариф |
|-----------|--------|-----------------|
| **Frontend** | Vercel | Да, без ограничений для личных проектов |
| **Backend** | Render | Да (засыпает после 15 мин бездействия) |
| **База данных** | Neon или Supabase | Да (PostgreSQL в облаке) |
| **Хранилище файлов** | Supabase Storage | Да (PDF-экспорт, аватары) |

**Vercel** — деплой одной командой `git push`, автоматические превью для каждой ветки, настраивается за 5 минут.

### Структура проекта (монорепо)

```
necromunda-app/
├── frontend/               # React + Vite + TypeScript
│   ├── src/
│   │   ├── components/     # UI-компоненты
│   │   ├── pages/          # Страницы (правила, банды, кампания)
│   │   ├── store/          # Zustand — глобальное состояние
│   │   └── api/            # React Query хуки для запросов к API
│   └── package.json
│
├── backend/                # Node.js + Express + TypeScript
│   ├── src/
│   │   ├── routes/         # Маршруты API
│   │   ├── controllers/    # Логика обработки запросов
│   │   ├── middleware/      # Авторизация, валидация
│   │   └── prisma/         # Схема базы данных
│   └── package.json
│
├── data/                   # JSON-файлы с игровыми данными
│   ├── factions/           # Фракции и типы бойцов
│   ├── weapons/            # Профили оружия
│   └── skills/             # Навыки и спецправила
│
└── README.md
```

> **Совет для старта:** игровые данные (фракции, оружие, правила) удобнее хранить в JSON-файлах на этапе MVP — это избавляет от необходимости настраивать БД с первого дня. Перенести в PostgreSQL можно позже.

### Почему не другие варианты

| Технология | Причина отказа |
|-----------|---------------|
| **Angular** | Высокий порог входа, избыточен для данного масштаба |
| **Vue** | Хорош, но меньше русскоязычных материалов чем у React |
| **Next.js** | SSR избыточен, усложняет деплой и разработку |
| **Django / Laravel** | Другой язык (Python/PHP), нет единства со стеком |
| **MongoDB** | Документарная БД хуже подходит для строгих реляционных данных |
| **Redux** | Слишком сложен, Zustand делает то же самое проще |
| **GraphQL** | Избыточен, REST API достаточно для этого проекта |
| **Docker** | Добавляет сложность при поддержке без DevOps-знаний |

### С чего начать (порядок освоения)

1. **HTML + CSS + JavaScript** — основа (2–4 недели, если не знакомы)
2. **TypeScript** — базовые типы (1 неделя)
3. **React** — компоненты, хуки, роутинг (3–4 недели)
4. **Node.js + Express** — создание REST API (2–3 недели)
5. **Prisma + PostgreSQL** — работа с базой данных (1–2 недели)
6. **Деплой на Vercel + Render** — публикация проекта (1 день)
